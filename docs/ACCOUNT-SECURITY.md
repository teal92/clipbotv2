# Account security and password recovery

Account sections contain General, Plans & Billing, Edit Profile and Settings. The username is the display name, must be unique case-insensitively across existing account names and profile usernames, and can change once every six calendar months in UTC after a successful claim. Profile picture and password can also be changed. Legacy names remain visible until a first username claim. Sign-in uses email. Email is read-only until a separate verified-email-change workflow exists.

Passwords are never returned by APIs or shown in C2. They are salted PBKDF2-SHA256 hashes (600,000 iterations). An authenticated change requires the current password, preserves that session, revokes other browser sessions and local worker devices/pairings, and invalidates pending reset links.

Recovery uses the existing support SMTP configuration: CLIPBOT_REPORT_FROM, CLIPBOT_REPORT_SMTP_HOST, CLIPBOT_REPORT_SMTP_PORT (465 or 587), CLIPBOT_REPORT_SMTP_USERNAME and CLIPBOT_REPORT_SMTP_PASSWORD. Keep credentials in server environment variables. TLS and certificate verification are mandatory. Configure CLIPBOT_ORIGIN to the public HTTPS origin; HTTP is accepted only for local loopback development. Recovery mail goes exclusively to the selected customer's stored email, never the report inbox or an operator-entered recipient.

C2's owner-confirmed reset action requests an emailed link. The owner cannot choose, read or see a customer's password or reset secret. Without working SMTP, the action reports unavailable; it does not pretend to send mail. No actual messages or customer resets are needed for automated tests.

Public recovery is /reset-password.html. Forgot-password requests always return the same message, including unknown emails or unavailable SMTP. Reset links put a random 256-bit secret in the URL fragment so it is not sent in normal HTTP access requests. The page clears the fragment immediately and keeps the secret only in memory. Reloading after clearance requires reopening the email link. Tokens are hashed at rest, expire in 15 minutes, work once, and are invalidated by newer requests. Successful redemption changes the password, revokes all browser sessions and local workers, and records email ownership verification.

Limits persist in SQLite: public request IP 10/15 minutes, email 3/15 minutes, global public requests 100/15 minutes, customer sends 3/hour and global sends 50/day. Redemption is capped at 10/IP/15 minutes and 100 globally/15 minutes. SMTP is attempted once with a 15-second timeout; failed or uncertain delivery invalidates the link and is not automatically retried. A mail-server acceptance is not proof of inbox delivery.

Images accept JPEG, PNG or WebP up to 128 KB and 4 million pixels. The server decodes, rejects animations, strips metadata and reencodes a 256-pixel square PNG. SVG and remote image URLs are rejected.

Tests: tests/test_account_profile.py covers ownership, CSRF, password changes and revocations, image validation, username conflicts and durable auth limits. tests/test_account_recovery.py uses injected fake mail to cover exact recipients, no plaintext token persistence/response, expiry, single-use atomic claims, unavailable SMTP, generic public responses and reset invalidation after password changes. tests/account-profile-ui.test.mjs covers escaped fields, section controls and delayed upload session changes.

This is not a complete launch-readiness claim. Public registration remains closed, and MFA, verified email-change and further operational security review are separate work.


Release audit, 2026-10-13: authentication checked at the password verifier, session authorization, request origin/CSRF and durable abuse-limit layers. Distributed login guesses against one account are now bounded as well as per-IP attempts. Signup records the current policy version before account creation. Retired Owner Metrics routes and frontend assets are removed; C2 uses a separate private service key. No real customer resets, email sends, social posts or paid AI requests were used in verification.

Dependency control: server requirements are pinned to reviewed names/versions and committed SHA-256 wheel hashes, using the official PyPI index and binary artifacts only. tools/dependency_policy.py rejects unexpected sources and unreviewed versions. These controls reduce package substitution and hallucinated dependency risks; they do not prove a publisher's package is harmless. Worker dependencies and build tools still require a separate lock/provenance review. Davey receives no executable tools, never installs dependencies and rejects unexpected non-text provider content.

Current operational limits: no outgoing SMTP connection is configured, so reports are stored and password recovery is unavailable. MFA, proactive signup email verification, breached-password screening, dependency vulnerability scanning, privacy retention/deletion automation and legal review remain launch work. Account export/deletion requests currently use the published support inbox and require ownership verification. This audit does not certify every security or legal criterion.


Production account update, October 13, 2026: usernames are now the display name, checked case-insensitively against assigned usernames and legacy names. Assignments/changes are atomic and limited to one per six calendar months in UTC. Old assigned usernames without a recorded change date begin the interval at migration; unassigned legacy names can be claimed once. Password signup/change/reset enforce 12–128 characters, uppercase/lowercase/number/special and a small common-pattern block. The checklist measures rules compliance, not password entropy; existing login credentials remain supported. Policies now identify YOUR COMPANY NAME, YOUR STATE, YOUR COUNTRY and publish downloadable production documents; legal enforceability is not certified.
